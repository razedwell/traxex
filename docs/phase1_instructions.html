How to use this doc + guiding principles

  • YAGNI — Phase 1 builds thin factories and helpers, not production-grade frameworks. Skip retry policies, circuit breakers, connection retry loops, and generic abstractions until a service actually needs them.
  • Single responsibility — Each shared/ package does one thing: load config, open a pool, create a client. Business logic stays in services/*/internal/.
  • Dependency direction — shared/ must never import from services/. Services import shared. This keeps your monorepo acyclic.
  • Verify as you go — Every step ends with a "done when" checklist. Don't move on until the verify commands pass.
  • Recommended order — Follow the numbered steps below. Config and docker-compose come first because everything else depends on them.
recommended build order:
1. Makefile fixes → 2. docker-compose + .env → 3. config → 4. traxerr → 5. postgres → 6. redis → 7. observability → 8. kafka

Services should return domain-meaningful errors (NOT_FOUND, UNAUTHORIZED), not raw fmt.Errorf("user not found") strings. Handlers translate these to HTTP status codes or gRPC statuses. One error type across all services keeps handler code uniform.

What you already have

What to implement
  • Define constant codes in code.go (start with 5–6, add more in Phase 2)
  • Implement error interface on Traxerr
  • Constructor helpers: New(code, msg), Wrap(code, msg, cause)
  • IsCode(err, code) helper for errors.Is-style checks
  • Stub ToGRPCStatus(err) codes.Code — full mapping in Phase 2 when gRPC handlers exist
Interface / pseudo-code
// code.go
type Code string

const (
    CodeNotFound       Code = "NOT_FOUND"
    CodeUnauthorized   Code = "UNAUTHORIZED"
    CodeInvalidInput   Code = "INVALID_INPUT"
    CodeConflict       Code = "CONFLICT"
    CodeInternal       Code = "INTERNAL"
    CodeUnavailable    Code = "UNAVAILABLE"
)

// errors.go
type Traxerr struct {
    Code    Code
    Message string
    Cause   error          // optional — use errors.Unwrap
    Details map[string]any  // optional context for logs/API
}

func (*Traxerr) Error() string           // return Message (or Message + Cause)
func (*Traxerr) Unwrap() error          // return Cause

func New(code Code, msg string) *Traxerr
func Wrap(code Code, msg string, cause error) *Traxerr
func IsCode(err error, code Code) bool

// grpc.go — stub for now
func GRPCCode(code Code) int  // maps to google.golang.org/grpc/codes
// NOT_FOUND → codes.NotFound, UNAUTHORIZED → codes.Unauthenticated, etc.
Don't build yet: HTTP status mapping (Phase 2 with oapi-codegen), error JSON serialization for REST responses, i18n, error catalog YAML. Keep it Go-native.

shared/kafka — producer/consumer helpers
Thin wrapper over segmentio/kafka-go. Context-aware, no retry framework.
not started ▶
Why

Messaging (Phase 3) and Notification (Phase 5) services publish/consume Kafka events. A shared wrapper standardizes broker config, writer/reader creation, and graceful close. You won't use it until Phase 3, but having the factory ready keeps Phase 3 focused on business logic.

Library choice

Use segmentio/kafka-go — pure Go, no CGO, simpler local dev than confluent-kafka-go. Matches the roadmap's "segmentio/kafka-go or confluent" option.

go get github.com/segmentio/kafka-go
Package layout + interfaces
shared/kafka/
├── producer.go
├── consumer.go
└── config.go   # optional — or reuse config.KafkaConfig

// producer.go
type Producer struct {
    writer *kafka.Writer
}

func NewProducer(cfg config.KafkaConfig, topic string) *Producer
// kafka.Writer{ Addr, Topic, Balancer: &kafka.LeastBytes{}}

func (p *Producer) Publish(ctx context.Context, key, value []byte) error
// writer.WriteMessages(ctx, kafka.Message{Key: key, Value: value})

func (p *Producer) Close() error

// consumer.go
type Consumer struct {
    reader *kafka.Reader
}

func NewConsumer(cfg config.KafkaConfig, topic, groupID string) *Consumer
// kafka.Reader{ Brokers: cfg.Brokers, Topic, GroupID }

func (c *Consumer) Read(ctx context.Context) (kafka.Message, error)
// reader.ReadMessage(ctx) — respects ctx cancellation

func (c *Consumer) Close() error
Design decisions
  • One writer per topic (producer) — kafka-go best practice
  • Pass context.Context on Publish/Read — enables timeout and cancellation
  • Don't wrap messages in custom structs yet — raw []byte until you define event schemas in Phase 3
  • Export Close() on both — call from main's shutdown handler
Don't build yet: Retry with exponential backoff, dead-letter queue, idempotent producer, schema registry, consumer offset commit abstraction, trace header injection (Phase 6).
